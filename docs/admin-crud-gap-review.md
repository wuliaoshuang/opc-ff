# 后台管理 CRUD 缺口复盘

日期：2026-05-26

目标：后台管理模块不能只做“展示 + 少量审核按钮”，要按可运营系统补齐常规管理能力。后续每补一批功能，同步补 store / 组件测试，减少浏览器手工点测。

## 已接入测试框架

- 使用 Vitest + jsdom + Testing Library。
- 命令：
  - `npm test`：跑单测。
  - `npm run test:watch`：开发时监听。
- 当前覆盖：
  - 大管理员、四个区域管理员账号种子数据。
  - 区域管理员登录、停用、启用、重复账号/手机号拦截。
  - 后台创建合伙人账号、资源关键词提取、重复账号/手机号拦截。
  - 后台重置密码后旧密码失效、新密码可登录。
  - store 层保护最大权限大管理员不能被停用或删除。
  - 四区区域可见性。
  - 线索管理、总项目表、激励任务、分佣结算、产品货架、培训内容、客户绑定的基础 CRUD / 状态流转。
  - 客户绑定控制台新增、编辑、删除绑定并记录历史。
  - 贴牌配置保存、审核状态更新、删除配置。

## 建议补齐顺序

1. P0 后台运营闭环：
   账号管理、合伙人管理、线索管理、总项目表、激励管理、分佣结算。
2. P1 配置和内容管理完善：
   客户绑定、培训内容、AIGC 模板、贴牌配置、产品货架。
3. 每个模块补齐时至少加三类测试：
   新增成功、编辑/状态流转成功、删除/禁用/权限拦截成功。

## 验收方式

- 先跑命令：
  - `npm test`
  - `npm run lint`
  - `npm run build`
- 再由人工按模块抽查关键路径；不再把浏览器手工点击作为主要回归手段。
